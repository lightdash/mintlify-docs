[dbt](https://docs.getdbt.com/docs/introduction?version=2) is the industry-standard tool for transforming data in your warehouse. You write modular transformations as plain SQL `select` statements, and dbt handles the dependencies between them, builds the resulting tables and views, and tests them.

Lightdash reads that project and adds a layer on top. Your dbt models define *what the tables are*; the Lightdash metadata in your YAML defines *what they mean* — which columns are dimensions, which aggregations are metrics, how models join. Together those become a semantic layer that you and your agents query to build charts and run analyses that stay consistent no matter who asks.

Alongside your models, the `lightdash/` directory in your repository holds the content built on that layer: dashboards, charts, agents, and data apps, versioned as code like everything else. See [content as code](/workflow/content-as-code).

For the field-level YAML reference, see [tables](/semantic-layer/tables), [dimensions](/semantic-layer/dimensions), and [metrics](/semantic-layer/metrics).
