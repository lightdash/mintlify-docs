Semantic Studio is the **Semantic Layer** page in Lightdash. It shows every model in a project, how its tables join, and, for developers, lets you change the semantic layer by chatting with an AI agent instead of editing YAML by hand.

## Browse your semantic layer

On the nav bar, click **Browse** → **Semantic Layer**. The page lists the project's modeled explores, [live data sources](/integrations/live-data-sources) and [external sources](/explore/external-sources). Select a model to see its fields.

Modeled (dbt) explores have two more tabs:

- **Lineage** draws the dbt models each table is built from, the base table, and every joined table. Click a table to see what it joins to, the relationship, the join type and the full join condition. Joins that fan out are colored differently, so you can spot them before building a chart on the wrong grain.
- **Pre-aggregates** lists the model's [pre-aggregates](/semantic-layer/pre-aggregates) and the charts that ran on the warehouse in the last 7 days. It appears when pre-aggregates are enabled on your instance.

Live data sources and external sources have neither tab.

## Change the semantic layer with the chat

<Info>
  Editing is off by default. [Contact Lightdash support](mailto:support@lightdash.com) to turn it on for your organization. On a self-hosted instance, add `semantic-studio-editing` to [`LIGHTDASH_ENABLE_FEATURE_FLAGS`](/self-host/customize-deployment/environment-variables#feature-flags).
</Info>

You need developer access to the project. If the project's models live in a Git repository, you also need permission to manage its source code. Other people can browse the page but can't see or open changes.

1. On the **Semantic Layer** page, open the Studio chat and describe the change, such as adding a metric or a description.
2. The agent works on a draft of your change. Open **Sources** to read or edit the YAML yourself; Studio checks it against the dbt schema as you type.
3. Click **Try it** to explore your changes in a modal before they're live.
4. Publish the draft, or merge its pull request.

How a change goes live depends on where the project's models are kept:

| Models are kept in | The agent changes them | Goes live when you |
| --- | --- | --- |
| Git (GitHub, GitLab or Bitbucket Cloud) | Through a pull request | Merge the pull request |
| Lightdash, with no dbt project | In a draft | Publish the draft |

On a Git project, saving your own edits in **Sources** adds a commit to the change's pull request. Saves are refused while the agent is editing the same change.

## Published and drafts

**Published** is what everyone sees. Each change you start is a **draft**, and the header shows it as `Draft: <name>`. Use the picker beside the **Models** and **Sources** tabs to switch between **Published**, **Your drafts**, **All drafts** and **New draft**.

- You have one checked-out draft per project, and the page follows it across browsers and devices.
- Teammates' drafts open read-only, each file compared with how it was before that draft, with the parts they're changing marked on the model.
