<Tip>
Most of these patterns don't need hand-written SQL. [Formula table calculations](/explore/table-calculations/formulas) have window functions such as `LAG`, `RANK`, `RUNNING_TOTAL`, and `MOVING_AVG`, and the [row functions](/explore/table-calculations/functions/row-functions) and [pivot functions](/explore/table-calculations/functions/pivot-functions) cover previous rows and pivot columns.
</Tip>

Each template is a window function over your results table. Swap the `${table.column_...}` placeholders for your own fields, using the `${table_name.field_name}` format or autocomplete.

The `ORDER BY` columns in a template should match the dimensions and sort order of your results table. Add every dimension in the results table, in the same order, so each row compares against the row directly above it. Columns sort ascending by default; add `DESC` to sort descending.

For the percent templates, set the table calculation's format to **Percent** in the **Format** tab so the result shows as a percentage instead of a ratio.

## Percent change from previous

Divides each value by the value in the row above it, using `LAG` ordered by your results table's dimensions, then subtracts 1. The first row has no previous value, so it returns `NULL`.

```sql
(
  ${table.column_i_want_to_compare} /
    LAG(${table.column_i_want_to_compare}) OVER (
      ORDER BY
        ${table.column_I_want_to_order_by},
        ${table.optional_other_column_I_want_to_order_by}
    )
) - 1
```

On a pivot table, table calculations run on the results before they're pivoted, so the pivoted dimension must be in the query. To compare each pivot column with the one before it for the same row, partition by the row dimension and order by the pivoted dimension. This month-over-month version uses `orders.country` as the row dimension and `orders.order_date_month` as the pivot:

```sql
${orders.total_revenue} /
  NULLIF(
    LAG(${orders.total_revenue}) OVER (
      PARTITION BY ${orders.country}
      ORDER BY ${orders.order_date_month}
    ),
    0
  ) - 1
```

For year over year on monthly data, use `LAG(${orders.total_revenue}, 12)`. `LAG` counts rows, not months, so a month with no row for that country shifts the comparison.

## Percent of previous value

Divides each value by the value in the row above it, using `LAG` ordered by your results table's dimensions. The first row returns `NULL`.

```sql
${table.column_i_want_to_compare} /
  LAG(${table.column_i_want_to_compare}) OVER (
    ORDER BY
      ${table.column_I_want_to_order_by},
      ${table.optional_other_column_I_want_to_order_by}
  )
```

## Percent of column total

Divides each value by the sum of the whole column. The empty `OVER()` makes the window every row in the results table.

```sql
${table.column_i_want_to_see_the_percent_of_total} /
  SUM(${table.column_i_want_to_see_the_percent_of_total}) OVER()
```

## Percent of group total

Divides each value by the sum of its group. `PARTITION BY` splits the rows into groups by `column_i_want_to_group_by`, such as a month or a pivot dimension, and the sum restarts for each group.

```sql
${table.column_i_want_to_see_the_percent_of_total} /
  SUM(${table.column_i_want_to_see_the_percent_of_total}) OVER (
    PARTITION BY
      ${table.column_i_want_to_group_by}
  )
```

## Rank in column

Numbers the rows by the column you want to rank. `DESC` gives the largest value rank 1; `ASC` gives the smallest value rank 1. To rank within groups, add a `PARTITION BY` clause before `ORDER BY`.

```sql
ROW_NUMBER() OVER (
  ORDER BY
    ${table.column_i_want_to_rank} DESC
)
```

## Running total

Sums each value with every value above it. The window runs from the first row (`UNBOUNDED PRECEDING`) to the current row, in the order of your results table's dimensions.

```sql
SUM(${table.column_I_want_to_sum}) OVER (
  ORDER BY
    ${table.column_I_want_to_order_by},
    ${table.optional_other_column_I_want_to_order_by}
  ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW
)
```

## Rolling window

Sums the current row and the `N` rows before it, so a four-week window uses `N = 3`. Dividing one rolling sum by a second rolling sum gives a rolling average or ratio; drop the second `SUM` for a plain rolling total. Replace `N` with a number before you run it.

```sql
SUM(${table.column_I_want_to_sum}) OVER (
  ORDER BY
    ${table.column_I_want_to_order_by}
  ROWS BETWEEN N PRECEDING AND CURRENT ROW
) /
  SUM(${table.second_column_I_want_to_sum}) OVER (
    ORDER BY
      ${table.column_I_want_to_order_by}
    ROWS BETWEEN N PRECEDING AND CURRENT ROW
  )
```
