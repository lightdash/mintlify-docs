## Formatting your fields in your .yml files

Sometimes the format of things in your dbt project is different to how you want it to look in Lightdash. That's okay! We've built a bunch of features to help you to format the fields in your dbt project so that the data in your Lightdash project looks exactly like you want it to 🥸

### The [metrics](/semantic-layer/metrics#metric-configuration) and [dimensions](/semantic-layer/dimensions#dimension-configuration) reference docs

We're going to go through formatting your fields in more detail below, but you can see a list of these configurations and all of the other properties you can customize for your fields in the [dimensions reference doc](/semantic-layer/dimensions#dimension-configuration) and [metrics reference doc](/semantic-layer/metrics#metric-configuration).

### Hiding fields

Sometimes, we have a bunch of columns in our YAML files that we might not want to include in Lightdash. For example, columns with PII data, or the same date data, but at different levels of date granularity.

It's easy to hide columns from Lightdash. All you need to do is add two words to your column: `hidden: true`.

In your dbt YAML file, it'll look something like this:

<CodeGroup>

```yaml dbt v1.10+
models:
  - name: users
    columns:
      - name: first_name
        config:
          meta:
            dimension:
              hidden: true
```

```yaml dbt v1.9 and earlier
models:
  - name: users
    columns:
      - name: first_name
        meta:
          dimension:
            hidden: true
```

</CodeGroup>

This `hidden: true` tag can be added to [dimensions](/semantic-layer/dimensions#hiding-dimensions-in-lightdash) and [metrics](/semantic-layer/metrics#hiding-metrics-in-lightdash) in Lightdash.

### Grouping fields

We can group both metrics and dimensions in Lightdash by adding the `group_label` tag to our .yml files.

#### Grouping dimensions

If, for example, we wanted to put all of our user's name related dimensions under a different section, we could add in the `group_label` tag, like this:

<CodeGroup>

```yaml dbt v1.10+
models:
  - name: users
    columns:
      - name: first_name
        config:
          meta:
            dimension:
              group_label: 'User name'

      - name: last_name
        config:
          meta:
            dimension:
              group_label: 'User name'
```

```yaml dbt v1.9 and earlier
models:
  - name: users
    columns:
      - name: first_name
        meta:
          dimension:
            group_label: 'User name'

      - name: last_name
        meta:
          dimension:
            group_label: 'User name'
```

</CodeGroup>

Then, in the Explore view, our two dimensions would be grouped together under a collapsible section called `User name`, like this:

<Frame>
  <img src="/images/explore/formatting-your-fields/grouping-dimensions.png" alt="Dimensions grouped under a collapsible 'User name' section in the Explore view"/>
</Frame>

To learn more about the dimension `group_label` configuration, check out our [dimension reference doc](/semantic-layer/dimensions#group-label).

#### Grouping metrics

You can do the same with metrics. For example, let's group all of our order-related metrics together:

<CodeGroup>

```yaml dbt v1.10+
models:
  - name: orders
    columns:
      - name: order_id
        config:
          meta:
            metrics:
              unique_order_count:
                type: count_distinct
                group_label: 'Order metrics'

      - name: order_amount
        config:
          meta:
            metrics:
              total_order_amount:
                type: sum
                group_label: 'Order metrics'
```

```yaml dbt v1.9 and earlier
models:
  - name: orders
    columns:
      - name: order_id
        meta:
          metrics:
            unique_order_count:
              type: count_distinct
              group_label: 'Order metrics'

      - name: order_amount
        meta:
          metrics:
            total_order_amount:
              type: sum
              group_label: 'Order metrics'
```

</CodeGroup>

To learn more about the metric `group_label` configuration, check out our [metric reference doc](/semantic-layer/metrics#group-label).

### Relabelling fields

Sometimes the names of things in our dbt project don't match up to what we want to call things in Lightdash. You can easily update the labels of things using the `label` tag in your .yml files.

#### Relabelling dimensions

For example, if we wanted to relabel our dimension `user_id` to be called `Unique ID`, we could add the `label` tag, like this:

<CodeGroup>

```yaml dbt v1.10+
models:
  - name: users
    columns:
      - name: user_id
        config:
          meta:
            dimension:
              label: 'Unique ID'
```

```yaml dbt v1.9 and earlier
models:
  - name: users
    columns:
      - name: user_id
        meta:
          dimension:
            label: 'Unique ID'
```

</CodeGroup>

To learn more about the dimension `label` configuration, check out our [dimension reference doc](/semantic-layer/dimensions#label).

#### Relabelling metrics

Same goes for metrics. If we wanted to relabel our metric `unique_user_id_count` to `Total users`, we could use the `label` tag, like this:

<CodeGroup>

```yaml dbt v1.10+
models:
  - name: users
    columns:
      - name: user_id
        config:
          meta:
            metrics:
              unique_user_id_count:
                type: count_distinct
                label: 'Total users'
```

```yaml dbt v1.9 and earlier
models:
  - name: users
    columns:
      - name: user_id
        meta:
          metrics:
            unique_user_id_count:
              type: count_distinct
              label: 'Total users'
```

</CodeGroup>

To learn more about the metric `label` configuration, check out our [metric reference doc](/semantic-layer/metrics#label).

### Changing a field's table

When you create a dimension in Lightdash, it'll automatically be listed under the table that it was created in, in your dbt project. So, if you create a dimension in your `users.yml` model, it will be listed under the `Users` table in Lightdash.

But, sometimes, you might want to move your dimension to a different table in Lightdash. You can do this by using the `table` tag.

#### Changing a dimension's table

For example, let's say I have a dimension about someone's `first_name`, but I actually want this to appear under a different table in Lightdash, called `Persons`, instead of `Users`, which is the table it would appear under by default (because that's the base table of the model where this dimension sits). I can use the `table` tag to do this, like so:

<CodeGroup>

```yaml dbt v1.10+
models:
  - name: users
    columns:
      - name: first_name
        config:
          meta:
            dimension:
              table: 'persons'
```

```yaml dbt v1.9 and earlier
models:
  - name: users
    columns:
      - name: first_name
        meta:
          dimension:
            table: 'persons'
```

</CodeGroup>

To learn more about the dimension `table` configuration, check out our [dimension reference doc](/semantic-layer/dimensions#table).

#### Changing a metric's table

Same goes for metrics. If I have a metric about a `unique_user_id_count`, but I actually want this to appear under a different table in Lightdash, called `Persons`, instead of `Users`, which is the table it would appear under by default (because that's the base table of the model where this dimension sits), I can use the `table` tag to do this, like so:

<CodeGroup>

```yaml dbt v1.10+
models:
  - name: users
    columns:
      - name: user_id
        config:
          meta:
            metrics:
              unique_user_id_count:
                type: count_distinct
                table: 'persons'
```

```yaml dbt v1.9 and earlier
models:
  - name: users
    columns:
      - name: user_id
        meta:
          metrics:
            unique_user_id_count:
              type: count_distinct
              table: 'persons'
```

</CodeGroup>

To learn more about the metric `table` configuration, check out our [metric reference doc](/semantic-layer/metrics#table).

### Describing fields

You can add descriptions to your dimensions and metrics, which will appear when you hover over the field name's `(i)` icon in the Explore view.

#### Describing dimensions

If your dimension already has a `description` tag for dbt docs, Lightdash will automatically use this as the field's description too! But, if you want to override this with a different description, you can add the `description` tag under the `dimension` meta tag, like this:

<CodeGroup>

```yaml dbt v1.10+
models:
  - name: users
    columns:
      - name: user_id_sha64
        description: 'Unique identifier for a user, hashed using SHA-64 algorithm.'
        config:
          meta:
            dimension:
              description: 'A unique identifier for a user, like a backstage pass but less exciting. No groupies included.'
```

```yaml dbt v1.9 and earlier
models:
  - name: users
    columns:
      - name: user_id_sha64
        description: 'Unique identifier for a user, hashed using SHA-64 algorithm.'
        meta:
          dimension:
            description: 'A unique identifier for a user, like a backstage pass but less exciting. No groupies included.'
```

</CodeGroup>

To learn more about the dimension `description` configuration, check out our [dimension reference doc](/semantic-layer/dimensions#description).

#### Describing metrics

Metrics are a little different to dimensions. Because metrics are something that are defined by us in the `meta` tag (they're not something that already exists in our dbt project), they don't have a `description` field in dbt. So, if we want to add a description to them, we just need to add it using the `description` tag, under our metric's definition, like this:

<CodeGroup>

```yaml dbt v1.10+
models:
  - name: users

    columns:
      - name: user_id_sha64

    config:
      meta:
        metrics:
          count_unique_user_ids:
            type: count_distinct
            sql: ${TABLE}.user_id_sha64
            description: 'Unique count of user ids'
```

```yaml dbt v1.9 and earlier
models:
  - name: users

    columns:
      - name: user_id_sha64

    meta:
      metrics:
        count_unique_user_ids:
          type: count_distinct
          sql: ${TABLE}.user_id_sha64
          description: 'Unique count of user ids'
```

</CodeGroup>

To learn more about the metric `description` configuration, check out our [metric reference doc](/semantic-layer/metrics#description).

### Hiding a table's name from a field's full name

By default, the full name of a dimension or metric in Lightdash includes the table name, like `Users First name` or `Orders Total order amount`. You can hide the table name from the field's full name by adding the `hidden: true` tag under the `label` property of your table's `meta` tag (not the dimension or metric's `meta` tag).

For example, if we wanted to hide the `Users` table name from the `First name` dimension, so it just appears as `First name` instead of `Users First name`, we could do this:

<CodeGroup>

```yaml dbt v1.10+
models:
  - name: users
    config:
      meta:
        label:
          hidden: true
    columns:
      - name: first_name
```

```yaml dbt v1.9 and earlier
models:
  - name: users
    meta:
      label:
        hidden: true
    columns:
      - name: first_name
```

</CodeGroup>

### Formatting your metrics and dimensions

Check out [this doc](/semantic-layer/dimensions#dimension-configuration) to see all of the other properties you can customize for dimensions, and [this one](/semantic-layer/metrics#metric-configuration) for all of the other properties you can customize for your metrics.

The `format` property accepts spreadsheet-style format strings to round, compact, add locale separators, and attach currency or unit symbols. These options apply to dimensions, metrics, and table calculations. The full option tables and format-expression examples live in the [metrics](/semantic-layer/metrics#format) and [dimensions](/semantic-layer/dimensions#format) references; the sections below walk through the common cases.

### Rounding

Rounding your metrics is easy to do using the `format` property in your YAML file.

#### Rounding dimensions

Like this:

<CodeGroup>

```yaml dbt v1.10+
models:
  - name: sales
    columns:
      - name: total_amount
        config:
          meta:
            dimension:
              format: '0' # rounds to the nearest whole number
```

```yaml dbt v1.9 and earlier
models:
  - name: sales
    columns:
      - name: total_amount
        meta:
          dimension:
            format: '0' # rounds to the nearest whole number
```

</CodeGroup>

Check out [this doc](/semantic-layer/dimensions#format) to see all the other compact values. to see all the other formatting options.

#### Rounding metrics

Same concept applies to metrics:

<CodeGroup>

```yaml dbt v1.10+
models:
  - name: sales
    columns:
      - name: amount
        config:
          meta:
            metrics:
              total_amount:
                type: sum
                format: '0' # rounds to the nearest whole number
```

```yaml dbt v1.9 and earlier
models:
  - name: sales
    columns:
      - name: amount
        meta:
          metrics:
            total_amount:
              type: sum
              format: '0' # rounds to the nearest whole number
```

</CodeGroup>

Check out [this doc](/semantic-layer/metrics#format) to see all the other formatting options.

### Adding currency symbols, percentages, or other symbols to your metrics and dimensions

You can add symbols to the beginning or end of your numbers using the `format` property.

#### Adding symbols to dimensions

For example, if we wanted to add a `$` to the beginning of our `total_amount` dimension, we could do this:

<CodeGroup>

```yaml dbt v1.10+
models:
  - name: sales
    columns:
      - name: total_amount
        config:
          meta:
            dimension:
              format: '"$"#,##0.00'
```

```yaml dbt v1.9 and earlier
models:
  - name: sales
    columns:
      - name: total_amount
        meta:
          dimension:
            format: '"$"#,##0.00'
```

</CodeGroup>

### Changing number separators for metrics and dimensions

You can change the separators used in your numbers, for example, from `1,000,000.00` to `1.000.000,00`, using the `format` property, combined with the `round` property.

#### Changing separators for dimensions

For example, let's say we want to change our number separators for our `total_amount` dimension, from `1,000,000.00` to `1.000.000,00`, we could do this:

### Using conditional formatting

You can use conditional formatting to highlight your metrics and dimensions based on their value. For example, you might want to highlight all values that are negative in red, or all values that are above a certain threshold in green.

To use conditional formatting, you need to use the `round` property, combined with the `format` property, and some rules that define the conditions.

<CodeGroup>

```yaml dbt v1.10+
models:
  - name: sales
    columns:
      - name: total_amount
        config:
          meta:
            metrics:
              total_amount:
                type: sum
                format: '[Red][<0]-#,##0;[Green][>=0]#,##0'
```

```yaml dbt v1.9 and earlier
models:
  - name: sales
    columns:
      - name: total_amount
        meta:
          metrics:
            total_amount:
              type: sum
              format: '[Red][<0]-#,##0;[Green][>=0]#,##0'
```

</CodeGroup>

## Formatting your fields in the Lightdash UI

You can also format your fields in the Lightdash UI. This is useful if you want to format your fields quickly without having to change your YAML files.

Currently you can format 2 types of fields in the Lightdash UI:

* Custom metrics ([reference](/explore/create-custom-fields#custom-metrics))
* Table calculations ([reference](/explore/table-calculations))


### Formatting metrics

<Info>
  Metrics formatting is currently only available for numeric metric types.
</Info>

You can adjust the formatting of your pre-defined metrics from the results table.

<Frame>
  <img src="/images/explore/formatting-your-fields/yaml-metric-formatting.png" alt="The formatting panel for a YAML metric opened from the results table, with type, round and compact options"/>
</Frame>

You can customize the formatting of your custom metrics when you create them, and later on from the results table.

<Frame>
  <img src="/images/explore/formatting-your-fields/custom-metric-format.png" alt="The Format section of the custom metric modal, with format type, rounding, compact and prefix or suffix fields" />
</Frame>

These are the formatting options available:

* `percent`: Formats your metric as a percentage, with the following options:

  * `round` value to your metric to round it to a certain number of decimal places
  * `separator`, e.g. from `.` to `,`

* `currency`: Formats your metric as a currency

  * `round` value to your metric to round it to a certain number of decimal places
  * `separator`, e.g. from `.` to `,`
  * `currency` symbol, e.g. from `$` to `£`
  * `compact` value to compact your metric to a certain unit, e.g. from `1,000,000` to `1M`

* `number`: Formats your metric as a number

  * `round` value to your metric to round it to a certain number of decimal places
  * `separator`, e.g. from `.` to `,`
  * `compact` value to compact your metric to a certain unit, e.g. from `1,000,000` to `1M`
  * `prefix` value to add a prefix to your metric, e.g. `+` or `-`
  * `suffix` value to add a suffix to your metric, e.g. `%`


### Formatting table calculations

On the results table, you can add a table calculation by clicking on the button on the right hand side of the section.

<Frame>
  <img src="/images/explore/formatting-your-fields/table-calculation-create.png" alt="The results table header with the button on the right that adds a table calculation" />
</Frame>

Once you've created your table calculation, you can format it by clicking on the `Format` tab:

<Frame>
  <img src="/images/explore/formatting-your-fields/table-calculation-format.png" alt="The Format tab of the table calculation editor, with the formatting type options" />
</Frame>

Next to the `Format` heading, a data type selector tells Lightdash what your table calculation returns: `Number`, `String`, `Date`, `Timestamp`, or `Boolean`. Lightdash can't work this out from your formula, so set it to match the value the calculation returns before you pick a formatting type — a table calculation that references a timestamp dimension needs its data type set to `Timestamp`, otherwise a custom date format is ignored and the raw value shows instead.

<Note>
  Switching the data type between a number and a date-like type (or back) resets the formatting type you've chosen, so set the data type first.
</Note>

The formatting types available depend on the data type you pick:

* `String` and `Boolean` have no formatting options — these always display as-is.

* `Date` and `Timestamp` offer:

  * `Default`: Lightdash's standard date or timestamp display
  * `Custom`: enter a spreadsheet-style date expression, e.g. `dddd hh:mm AM/PM`. Check out [this doc](/semantic-layer/metrics#format) for more example format expressions.

* `Number` offers:

  * `Plain`: no formatting applied
  * `Number`:

    * `round` value to your metric to round it to a certain number of decimal places
    * `separator`, e.g. from `.` to `,`
    * `compact` value to compact your metric to a certain unit, e.g. from `1,000,000` to `1M`
    * `prefix` value to add a prefix to your metric, e.g. `+` or `-`
    * `suffix` value to add a suffix to your metric, e.g. `%`

  * `Currency`:

    * `round` value to your metric to round it to a certain number of decimal places
    * `separator`, e.g. from `.` to `,`
    * `currency` symbol, e.g. from `$` to `£`
    * `compact` value to compact your metric to a certain unit, e.g. from `1,000,000` to `1M`

  * `Percent`:

    * `round` value to your metric to round it to a certain number of decimal places
    * `separator`, e.g. from `.` to `,`

  * `Bytes`: formats your metric as a byte size

    * unit system, `SI` (KB, MB, GB) or `IEC` (KiB, MiB, GiB)
    * `compact` value to compact your metric to a certain unit

  * `Custom`: enter a spreadsheet-style format expression, e.g. `#,##0.00`. Check out [this doc](/semantic-layer/metrics#format) for more example format expressions.
