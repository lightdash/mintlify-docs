title: "Attio"

The Attio [live data source](/integrations/live-data-sources) reads the records of one Attio object, such as companies, people, deals or a custom object. Lightdash turns each query into an Attio records query and shows the records Attio returns. CRM data stays in Attio. It's a [level 2](/integrations/live-data-sources#integration-levels) integration: its API filters records, without totals.

## Before you start

- **Live data sources enabled** for your organization. See [Live data sources](/integrations/live-data-sources).
- **Admin role** in the Lightdash project.
- **The object's slug,** such as `companies` or `deals`. Find it in your Attio workspace settings under **Objects**.
- **An access token** with the `record_permission:read` and `object_configuration:read` scopes. Create it in your Attio workspace settings under **Developers**.

To read several objects, add one source for each.

## Connect Attio

1. On the nav bar, click **Browse** → **Semantic Layer**.
2. In the sidebar, select **Live data sources**, then click **Add**.
3. Select **Attio**.
4. Enter a **Name**, such as `Attio companies`. People see this name in Explore and agents use it to refer to the source.
5. Enter the **Object** slug and the **Access token**, then click **Test access**.
6. Click **Add source**.

Lightdash adds a **Records** table to Explore. Lightdash sets the source's [explore prefix](/integrations/live-data-sources#explore-prefix) from its name, so give each Attio source its own.

## Dimensions

| Dimension | Notes |
| --- | --- |
| Record ID, URL | The record's ID and its link in Attio |
| Created | The day the record was created, in UTC |
| One for each attribute of the object | Read from Attio when you add the source, up to 300. Archived attributes and attribute types Lightdash can't read are skipped |

Select **Refresh fields** from the source's menu to read the attributes again after you add one in Attio. An attribute's field is named after its slug, so renaming an attribute's title in Attio doesn't change it.

Text, number, rating, date, checkbox, select, status, currency, name, email address and domain attributes can be filtered. Phone numbers, locations, record references, actor references and interactions can be shown but not filtered. The table has no metrics.

## Supported features

| Feature | Available |
| --- | --- |
| Filters on dimensions, with several values each | Yes |
| OR filters and nested filter groups | Yes |
| Filters on metrics | No |
| Table calculations, custom metrics and custom dimensions | No |
| Period-over-period comparisons, pivots and date zoom | No |

## Limits

| Limit | Value |
| --- | --- |
| Most rows per query | 9,999 |
| Timeout | 30 seconds per request |
| Queries at once | 3 per source |
| Calls per minute | 600 per source |
| Calls per hour | 20,000 per source |

When a query matches more than 9,999 records, Lightdash shows an error rather than a partial result. Add a filter.

## Example questions

- *"Companies created in the last 30 days."*
- *"Deals in the Won stage, with their value."*
- *"People at companies in the United Kingdom."*

## Troubleshooting

**Attio rejected the access token.** Create a new token and update the source.

**The access token can't read the object.** Give it the `record_permission:read` and `object_configuration:read` scopes.

**Attio has no object with that slug.** Check the slug in your workspace settings under **Objects**.

**Attio couldn't run this query.** Check the filter values, or use fewer filters.
