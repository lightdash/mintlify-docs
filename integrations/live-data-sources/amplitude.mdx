The Amplitude [live data source](/integrations/live-data-sources) reads one Amplitude project. Lightdash turns each query into a Dashboard REST API report, and Amplitude computes the totals, unique users, funnels and retention itself. Event data stays in Amplitude. It's a [level 3](/integrations/live-data-sources#integration-levels) integration: its API runs reports from a fixed menu.

## Before you start

- **Live data sources enabled** for your organization. See [Live data sources](/integrations/live-data-sources).
- **Admin role** in the Lightdash project.
- **The project's API key and secret key.** In Amplitude, open **Settings** → **Organization settings** → **Projects**, select the project, and copy both keys. Amplitude shows a secret key only when it creates it.
- **The project's data region**, US or EU. Projects you open at `analytics.eu.amplitude.com` are in the EU.

## Connect Amplitude

1. On the nav bar, click **Browse** → **Semantic Layer**.
2. In the sidebar, select **Live data sources**, then click **Add**.
3. Select **Amplitude**.
4. Choose the **Data region**, enter the **API key** and **Secret key**, then click **Test**. A working pair shows how many events the project tracks.
5. Under **Details**, check the **Name** and **Explore prefix**. People see the name in Explore and agents use it to refer to the source. The prefix is filled in from the name and can't be changed later. See [Explore prefix](/integrations/live-data-sources#explore-prefix).
6. Click **Add source**.

Lightdash adds **Events**, **Active users**, **Funnel**, **Retention** and **Sessions** tables to Explore, grouped under the source's name. To use a new key pair, delete the source and add it again; you can [reattach](/integrations/live-data-sources#explore-prefix) the deleted source so its charts keep working.

## Tables

Every table except **Sessions** can be filtered by these user properties: **Country**, **Region**, **City**, **Platform**, **OS**, **Device type**, **Language** and **App version**. **Events** and **Active users** can also be grouped by one of them at a time.

| Table | Dimensions | Metrics |
| --- | --- | --- |
| Events | Date, Date week, Date month, Event | Event count, Unique users, Events per user, Share of active users |
| Active users | Date, Date week, Date month | Active users, New users |
| Funnel | Step number, Step event | Users, Conversion from first step, Conversion from previous step, Average time to step (seconds) |
| Retention | Cohort, Cohort week, Cohort month, Days after start, Weeks after start, Months after start | Retained users, Cohort users, Retention rate |
| Sessions | Date | Average session length (seconds), Sessions per user |

- **Events** counts every event unless you filter **Event**. Filter it to up to 10 events, and add **Event** to the dimensions to compare them, because unique users can't be added across events.
- **Active users** needs a date dimension.
- **Funnel** reads the steps from the **Step event** filter, in the order you list the events, from 2 to 10. Filter **Conversion window (days)** to change the default of 30 days. The funnel covers the whole date range.
- **Retention** needs one of **Days**, **Weeks** or **Months after start**, which sets the grain; a cohort dimension must use the same grain. Without filters it counts new users who came back with any active event. Filter **Start event** and **Return event** to choose other events.
- **Sessions** reports per day.

Unique users, active users and rates are counted once per row. Choose a coarser date grain instead of adding rows together.

## Supported features

| Feature | Available |
| --- | --- |
| Filters on user properties | Yes, `is` and `is not` |
| OR filters and nested filter groups | No |
| Filters on metrics | No |
| Table calculations, custom metrics and custom dimensions | No |
| Pivots, date zoom and period-over-period comparisons | No |

## Limits

| Limit | Value |
| --- | --- |
| Default date range | Last 30 days, when the query has no date filter |
| Most rows per query | 5,000 |
| Calls per query | 20, one per event and metric |
| Timeout | 60 seconds |
| Queries at once | 3 per source |
| Calls per minute | 60 per source |
| Calls per hour | 1,000 per source |

Amplitude also limits the cost of the queries a project runs each hour, counted by days in the date range and the number of events and groupings. Long ranges with many events reach it sooner.

Custom user properties, lifecycle, stickiness, user paths, revenue and saved Amplitude charts aren't available from the Amplitude source.

## Example questions

- *"Daily active users over the last 90 days."*
- *"Weekly unique users of `Create Dashboard` and `Share Dashboard` for the last 12 weeks."*
- *"Conversion from `Sign Up` to `Complete Onboarding` to `Create Project` this month."*
- *"Weekly retention of new users over the last quarter."*

## Troubleshooting

**Amplitude rejected the API key and secret key.** Copy both keys again from the same project. A key pair belongs to one project.

**Amplitude denied access.** Check that the **Data region** matches the project: a key pair from an EU project is rejected in the US region, and the reverse.

**Amplitude rate limit reached.** Wait a few minutes, or shorten the date range or the number of events in the query.
