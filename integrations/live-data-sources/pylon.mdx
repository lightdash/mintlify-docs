The Pylon [live data source](/integrations/live-data-sources) reads one Pylon workspace. Lightdash turns each query into a Pylon search and shows the records Pylon returns. Support data stays in Pylon. It's a [level 2](/integrations/live-data-sources#integration-levels) integration: its API filters records, without totals.

## Before you start

- **Live data sources enabled** for your organization. See [Live data sources](/integrations/live-data-sources).
- **Admin role** in the Lightdash project.
- **A Pylon API token.** A Pylon admin creates it in **Settings** → **API Tokens**. The token decides which workspace the source reads.

## Connect Pylon

1. On the nav bar, click **Browse** → **Semantic Layer**.
2. In the sidebar, select **Live data sources**, then click **Add**.
3. Select **Pylon**.
4. Enter the **API token**, then click **Test**.
5. Under **Details**, check the **Name** and **Explore prefix**. People see the name in Explore and agents use it to refer to the source. The prefix is filled in from the name and can't be changed later. See [Explore prefix](/integrations/live-data-sources#explore-prefix).
6. Click **Add source**.

Lightdash adds **Issues**, **Accounts** and **Contacts** tables to Explore.

## Dimensions

Each table lists records, one row per issue, account or contact.

| Table | Dimensions |
| --- | --- |
| Issues | Number, Title, State, Source, Account, Account ID, Assignee, Team ID, Tags, Created, Created week, Created month, Created time, Updated, Updated week, Updated month, Resolved, Resolved week, Resolved month, First resolved, First response (minutes), Resolution time (hours), First response (business minutes), Resolution time (business hours), Touches, CSAT score, CSAT comment, Priority, First response due, First response breached, Resolution due, Resolution breached, Next reply due, Linked issue sources, Linked issue links |
| Accounts | Account ID, Name, Domain, Type, Owner, Tags, Created, Last customer activity, Last team activity |
| Contacts | Contact ID, Name, Email, Account, Account ID, Portal role |

Dates are UTC days. **Assignee** and **Owner** are teammates' email addresses. **Tags** are comma separated, and **Is** keeps records with any of the values. **State** is `new`, `waiting_on_you`, `waiting_on_customer`, `on_hold`, `closed` or a custom status.

**Created week**, **Updated week** and **Resolved week** are the Monday of the week, and the month fields are the first of the month, both in UTC. They have no filters of their own: filter **Created**, **Updated** or **Resolved** instead. An open issue has empty **Resolved** week and month.

The SLA fields come from the issue's own SLAs, not per-team ones. **Due** fields are deadlines with the time, in UTC. A **breached** field is true when the reply or resolution came after its deadline, or hasn't come and the deadline has passed, and empty without an SLA. **Priority** reads the custom field with the slug `priority`, and is empty when the workspace has none. **Linked issue** fields list the engineering issues linked to the issue, such as Linear or GitHub, comma separated. These fields can be shown and grouped by, but not filtered or sorted in Pylon.

None of the tables has metrics, so a query can't count or average records.

## Supported features

| Feature | Available |
| --- | --- |
| Filters on dimensions, with several values each | Yes |
| Filters on metrics | No |
| OR filters and nested filter groups | No |
| Table calculations, custom metrics and custom dimensions | No |
| Period-over-period comparisons, pivots and date zoom | No |

Account and assignee filters match by name and email. Lightdash looks the IDs up in Pylon first, which adds a call.

## Limits

| Limit | Value |
| --- | --- |
| Default date range | Last 30 days on **Created**, when an Issues query has no filter on it |
| Most rows per query | 9,999 |
| Timeout | 30 seconds per request |
| Queries at once | 2 per source |
| Calls per minute | 100 per source |
| Calls per hour | 3,000 per source |

When a query matches more than 9,999 records, Lightdash shows an error rather than a partial result. Narrow the date range or add a filter.

## Example questions

- *"Open issues assigned to me, oldest first."*
- *"Issues from the last 7 days that are still open."*
- *"Accounts with no customer activity this quarter."*

## Troubleshooting

**Pylon rejected the API token.** Ask a Pylon admin for a new token and update the source.

**The Pylon API token can't read this.** Pylon API tokens are created by admins in **Settings** → **API Tokens**. Ask an admin to create one.

**Pylon couldn't run this search.** Check the filter values.
