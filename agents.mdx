Build agents that investigate business performance, create analytics content, and help maintain the definitions behind your data. Lightdash brings together your semantic layer, reusable business context, and tools for acting on an analysis. Give each agent a focused job, then make it available where your team works.

## Build analytics workflows

An agent can investigate a change in a metric, compare segments or time periods, and return charts, tables, and explanations. Its metric queries use the definitions, joins, and access controls in your Lightdash semantic layer. [Data access settings](/agents/data-access) determine which explores and fields it can use and whether it can read query results.

Go beyond a conversation by enabling tools for the work you want to do. Agents can [create and edit saved charts and dashboards](/agents/enable-content-tools), build [data apps](/data-apps), or run [deep research](/agents/deep-research) that produces a report from a longer investigation. Each capability has its own enablement and permission requirements.

For data outside your modeled explores, [SQL mode](/agents/use-ai-agents#sql-mode) lets people with SQL Runner access run read-only warehouse queries. Those queries use warehouse permissions rather than semantic-layer controls.

## Build and improve shared context

Keep metric and field definitions in the semantic layer so agents and people work from the same meaning. Add [project context](/agents/agent-context) for shared terminology and table-selection rules, [knowledge documents](/agents/knowledge-documents) for longer reference material, and [custom skills](/agents/custom-agent-skills) for repeatable procedures such as investigating a KPI change.

These inputs are maintained resources your team can review and reuse. [Verified answers](/agents/verified-answers) give agents curated examples to reference. The [Issues board](/agents/issues) captures findings for review and can propose fixes to project context or semantic definitions through pull requests. Run [evaluation suites](/agents/create-evaluation-suites) to check answers as you change those resources.

## Bring agents into daily work

Work in [Lightdash conversations](/agents/use-ai-agents), connect an agent to [Slack](/agents/set-up-slack-agents), or [embed an agent](/embed/embed-ai-agents) in your own product. Schedule [recurring deliveries](/agents/use-ai-agents#schedule-a-recurring-delivery-from-a-conversation) when an analysis needs to reach your team regularly.

External assistants can use the [Lightdash MCP server](/agents/lightdash-mcp) to work with your analytics. In the other direction, connect [external MCP servers](/agents/connect-external-mcp-servers) to give a Lightdash agent tools from other services. For reviewed changes to your data project, use [AI writeback](/agents/ai-writeback); for other connected repositories, use the [AI coding agent](/agents/ai-coding-agent).

Start by [creating an agent](/agents/set-up-agents) with a clear audience and data scope. Organization admins control availability and provider defaults in [AI settings](/workspace-admin/ai-settings). Review conversations and tool activity through [Agent visibility](/agents/visibility), while [Autopilot](/agents/autopilot) runs scheduled project maintenance separately from team conversations.
