Lightdash AI agents answer questions about your data in natural language. Ask a question, inspect the chart or table behind the answer, and follow up to refine your analysis. You can work in the Lightdash app or [Slack](/integrations/slack#using-the-slack-integration).

## How agents answer questions

Agents use your semantic layer — metrics, dimensions, joins, and descriptions — to find the relevant data and build metric queries. Those queries follow your project's permissions and user attributes. [Data access settings](/agents/data-access) control which explores and fields an agent can use and whether it can read query results.

An agent can find existing charts and dashboards, generate visualizations, compare time periods, and explain results in text. Optional tools let it [create or edit saved content](/agents/enable-content-tools), build [data apps](/data-apps), or propose semantic-layer changes through [AI writeback](/agents/ai-writeback). Each feature's page covers its enablement and permissions.

For questions the semantic layer can't answer, [SQL mode](/agents/use-ai-agents#sql-mode) lets people with SQL Runner access ask the agent to run read-only warehouse SQL. Raw SQL sits outside semantic-layer controls; see [who can see what](/agents/data-access#who-can-see-what) before enabling it.

## Scope an agent to a clear job

Start with one audience, one business domain, and a set of questions the agent should answer. You can create separate agents for different teams, tasks, tones, or languages. Give each one a description that explains its scope and [tags](/agents/data-access#limiting-access-to-specific-explores-and-fields) that limit the data it can use.

Use instructions for behavior that should apply to every answer, knowledge documents for longer reference material, and skills for repeatable tasks. Keep shared metric and field definitions in the semantic layer. [Choose where guidance belongs](/agents/effective-analytics-with-agents#choose-where-guidance-belongs) covers these inputs in detail.

To build an agent, follow [Set up AI agents](/agents/set-up-agents). Start with its instructions and access scope, test representative questions, then add context or tools when you find a specific gap.

## Conversations and results

An agent uses the history of the current conversation to answer follow-up questions. Separate conversations start without that history. To ask a question, attach a file, or inspect a query, follow [Using AI agents](/agents/use-ai-agents).

Lightdash stores conversations and the query definitions behind their charts and tables until you delete the thread or its [retention window](/agents/thread-retention) expires. When you revisit a result, Lightdash queries the warehouse again, subject to [caching](/semantic-layer/caching). The agent's written reply stays as it was, so a chart can show different numbers from the surrounding text if the data or models have changed. The [data access setting](/agents/data-access) determines whether query results are also sent to the model.

[Autopilot](/agents/autopilot) performs scheduled project maintenance, such as finding broken charts and stale content. It runs separately from the conversational agents you ask questions here.
