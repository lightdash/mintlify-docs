The Big value option is for displaying a single value, well, big.

The Big value works for any type of value: string, numeric, boolean, you name it! We always display the first value from the field in your results table.

The options for Big value include:

- Selecting which field you want to use for your Big value.
- Updating the label below the Big value value.
- Adding a [comparison](#comparison) to the previous row or to another field
  - Show raw value or percentage change
  - Show red or green for positive or negative change
  - Label your comparison value
- Adding conditional formatting rules to change the color of the big value based on conditions.

For more visual control than these options offer — font size, spacing, layout — render the value with a [custom chart type](/visualizations/custom-charts) instead, installed from the chart library or built in [Chart Studio](/visualizations/chart-studio).

## Comparison

Turn on **Show comparison**, then set **Compare to**:

- **Previous row** compares the first row of your results with the second, so the query needs at least two rows, with the current value sorted first.
- **Same row** compares the big value with another **Field** in the first row, such as a [period-over-period](/explore/period-over-period) metric. This works when the query returns a single row.

The comparison shows as a pill next to the value. Hovering the pill shows the change and what it's compared to, for example `+500 compared to previous row`. That text is fixed: the **Comparison label** doesn't change it. The comparison label is a caption beside the pill, and it's hidden when the chart area is less than 70 pixels tall, such as on a one-row dashboard tile. It can show the [active granularity](#referencing-the-active-granularity-in-labels), but not the dates of the periods being compared.

## Empty results

If the query returns no rows, the big value shows **No data available**, like other chart types. If it returns a row whose value is null, it shows `∅` with the label underneath.

## Compact style

Numeric big values can be shortened using the **Compact** dropdown in the chart configuration panel. In addition to fixed styles (thousands, millions, billions, trillions), you can pick **Auto (K, M, B, T)** to let Lightdash choose the suffix based on the value's magnitude — so `1,500` renders as `1.50K` and `2,300,000` renders as `2.30M` without having to reconfigure the tile when the underlying value changes scale.

The Auto option is available for number and currency fields.

## Referencing the active granularity in labels

The label and comparison label accept the `${table_field.granularity}` placeholder to show the active date granularity — type `$` in the label field to pick from the available date dimensions. See [Referencing the granularity in chart labels](/explore/dashboards/date-zoom#referencing-the-granularity-in-chart-labels) for the full syntax and supported labels.

## Conditional formatting

You can apply conditional formatting to your big value to change its color based on specific conditions. To set up conditional formatting, go to the **Configure** tab, then select **Conditional formatting**.

### Adding a rule

Click the **+ Add** button to add a new rule. Each rule lets you:

1. Choose a color for light mode and dark mode separately.
2. Define one or more conditions that determine when the color is applied.

### Conditions

Each condition uses an operator and a value to compare against the big value. The available operators depend on the type of field you're displaying:

- **Numeric fields** support standard comparison operators (e.g., greater than, less than, equal to, between).
- **String dimensions** support `equals`, `not equals`, and `includes`.

You can add multiple conditions within a single rule. Multiple conditions within a rule are combined with **AND** logic, meaning all conditions must be met for the color to apply.

### Multiple rules

You can add multiple formatting rules. If two or more rules match, the rule that appears last in your list takes priority.

### Dark mode support

Each rule lets you set separate colors for light and dark mode, so your conditional formatting looks good regardless of which theme your viewers are using.
