A space can use one of the project's warehouse connections. Charts, dashboards and SQL charts in that space and its sub-spaces then query with that connection. People who view the space see results without entering personal warehouse credentials.

For example, a project has a connection that runs as an HR-scoped warehouse role. You create a space for the HR team and set it to that connection. Viewers of the space see the HR dashboards and need no credentials of their own. Developers who can edit the space can run SQL as the HR role in the SQL runner.

## Set a space's connection

You need permission to manage the project.

1. Open the space.
2. Click the space actions menu (`...`) and select **Edit space**.
3. Pick a connection in **Warehouse connection** and save.

The space page shows the connection the space uses. To remove the setting, pick **Inherit from parent space or project**.

## How queries pick a connection

When content runs a query, the connection comes from the first match in this list:

1. The connection of the space that holds the content.
2. The connection that the content itself uses, such as the connection of its explore or SQL chart.
3. The project's primary connection.

A sub-space uses its parent's connection unless it sets its own. A sub-space with its own connection overrides the parent for the content inside it.

Scheduled deliveries of content in the space run with the space's connection. If the space's connection requires personal credentials, each person's own credentials for that connection still apply. See [personal warehouse credentials](/workspace-admin/multiple-warehouse-connections#personal-warehouse-credentials).

## SQL runner

The SQL runner refuses a connection that a space uses, unless both are true:

- You can edit a space that uses that connection, with **Can edit** or **Full access**. See [space roles](/workspace-admin/roles#space-roles).
- You have permission to use the SQL runner.

Viewers of the space can see its content, but they can't write their own SQL on its connection.

## Limitations

- Explores that you open outside a space don't use a space's connection. They follow the project's usual rules.
- When you move content to another space, it uses the new space's connection.
- Content as code and [promotion](/explore/promote-content) don't carry the space's connection.
- The space's connection must point at the same warehouse that holds the content's tables. If it doesn't, the content's queries fail.
