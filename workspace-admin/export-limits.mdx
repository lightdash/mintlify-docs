The **Export limits** panel lets organization admins raise or lower the two values that bound how much data a query can return and how large a CSV or Excel export can be. Without an override, every organization inherits the instance defaults set by `LIGHTDASH_QUERY_MAX_LIMIT` and `LIGHTDASH_CSV_CELLS_LIMIT`.

Use this panel when a specific team needs to run wider or longer queries than the rest of the instance — for example, a single org on shared Cloud infrastructure that needs to export an 8M-cell CSV while keeping other orgs at the default.

## What you can configure

| Setting | What it controls | Inherits from |
| --- | --- | --- |
| **Maximum query rows** | The largest row limit a user can request from the explorer, SQL runner, or API. | `LIGHTDASH_QUERY_MAX_LIMIT` |
| **Maximum CSV/Excel cells** | The largest CSV or Excel export (rows × columns) before results are truncated. | `LIGHTDASH_CSV_CELLS_LIMIT` |

Both fields accept a positive integer. Leave a field empty to inherit the instance default.

The CSV/Excel cells value is capped server-side at the higher of `LIGHTDASH_CSV_MAX_LIMIT` (default 5,000,000) and the current `LIGHTDASH_CSV_CELLS_LIMIT`. The query rows value cannot exceed `LIGHTDASH_QUERY_MAX_LIMIT`. The panel shows the active ceiling next to each input.

The two limits are independent — raising the query-row limit does not change CSV export size, and vice versa. An **All results** export is bounded by the cell limit alone: it returns up to the cell limit divided by the number of columns (dimensions, metrics, and table calculations). With the default of 100,000 cells, a 10-column export holds up to 10,000 rows. To allow a larger export, set the cell limit to the number of rows you need multiplied by the number of columns.

## Google Sheets dashboard exports

Exporting a dashboard to Google Sheets is bounded separately, so the new spreadsheet stays inside Google's [cell limit per spreadsheet](#google-sheets-sync-limits). These limits are fixed and are not configurable from this panel:

| Limit | Value | What happens when it's reached |
| --- | --- | --- |
| Cells per export | 5,000,000 | Later tabs are trimmed so the spreadsheet stays inside Google's cap |
| Rows per tab | 50,000 | That tab is trimmed to the first 50,000 rows |

A tab trimmed by either limit is still created and still contains data — it's marked `Truncated` in the export's summary tab, along with the number of rows that were written. The export as a whole still succeeds.

## Google Sheets Sync limits

A [Google Sheets Sync](/integrations/google-sheets) writes the full result of its query to a tab on every run. These limits apply to each sync:

| Limit | Value | What happens when a sync reaches it |
| --- | --- | --- |
| Google's cells per spreadsheet, across all tabs, empty cells included | 20,000,000 | The sync fails before it writes, and the tab keeps its data. |
| Google's write requests per user | 60 per minute | Lightdash waits and tries again, and the sync stays on. |
| Lightdash's characters per cell | 50,000 | Lightdash cuts the value and ends it with `... [TRUNCATED]`. |

Lightdash writes a large result in batches to a hidden tab, then copies it into the synced tab in steps. Each step holds at most 100,000 rows, 500,000 cells, 12 MB, and 100,000 values of 64 or more characters. A sync of several hundred thousand rows takes a few minutes, and the synced tab shows its old data until Lightdash copies the new data in.

When a sync fails, the tab keeps its old data. In two cases, a failure can leave new rows at the top of the tab and old rows below:

- The copy takes more than one step, and a later step fails.
- The spreadsheet has no room for a second copy of the data, so Lightdash writes into the tab directly.

The email about the failure says which rows are new, for example "Rows 1-100,000 of the tab are new. The rows after them can be from the previous sync until a later run completes." See [When a sync fails](/integrations/google-sheets#when-a-sync-fails) for who gets the email and how to turn the sync back on.

To sync a result that doesn't fit, remove tabs that you don't use from the spreadsheet, or split the result across charts that sync to separate spreadsheets.

## Set per-organization limits

1. Go to **Settings → Organization → Limits**, which opens **Query and export limits**.
2. Enter a value for **Maximum query rows**, **Maximum CSV/Excel cells**, or both.
3. Click **Save**.

To revert to the instance default, clear the field and save.

Changes take effect immediately for new queries and exports. Existing scheduled deliveries pick up the new limit on their next run.

## How limits are enforced

| Surface | Behavior |
| --- | --- |
| Explorer and SQL runner row-limit selector | Maximum value is clamped to the org's effective query row limit. |
| CSV and Excel downloads from charts, dashboards, and underlying data | `All results` and `Custom` exports are truncated to the org's effective cell limit. `Table rows` exports return the rows already loaded and aren't capped. SQL runner and SQL chart downloads aren't capped by the cell limit. The download dialog shows the cell limit and, before you export, how many rows will be kept when the selection exceeds it. When truncation happens, a warning notification, **The results in this export have been limited.**, shows for about 5 seconds and then closes. |
| Scheduled deliveries (CSV, Excel) | Use the org's effective cell limit at run time. |
| Google Sheets Sync (recurring chart sync) | Bounded by the org's effective query row limit, not the cell limit, and by [Google's spreadsheet limits](#google-sheets-sync-limits). The sync fails instead of truncating when the chart's row limit is above the query row limit. |
| API responses for `/api/v1/org/settings` | Return the resolved effective values, falling back to the instance defaults when no override is set. |

<Note>
  Because **Maximum query rows** can't exceed `LIGHTDASH_QUERY_MAX_LIMIT`, an org admin on shared Cloud infrastructure can't raise the row ceiling for Syncs from this panel. Only a dedicated or self-hosted instance can, by changing the instance default itself.
</Note>
