Feature availability tells you whether you can use a feature in your Lightdash organization. It is separate from [feature maturity](/support/feature-maturity-levels): a Beta feature can require Enterprise, and a generally available feature can still need an add-on or a feature flag.

## Plan access

Plan badges identify eligible plans. When a page lists Cloud Pro and Enterprise, either plan meets that requirement. An add-on is a separate requirement, not a step between those plans.

### Cloud Pro

Cloud Pro is a Lightdash Cloud plan. A Cloud Pro badge identifies a feature available on that plan; the page states any other eligible plans and additional setup requirements.

### Enterprise

An Enterprise badge identifies a feature that requires Enterprise access. Self-hosted Enterprise features require a valid license key; see [enterprise features](/self-host/enterprise-features) for how to apply it. Cloud features can also need enablement for your organization.

### Add-ons

An add-on provides access to a feature separately from the base plan. The feature page identifies the add-on and any plan restrictions. For example, the [AI agents](/agents) pages identify the AI agents add-on where it is required.

For current plans and commercial details, see [Lightdash pricing](https://www.lightdash.com/pricing) or contact the Lightdash team.

## Deployment

### Cloud

A Cloud badge identifies a feature available only on Lightdash Cloud. Lightdash manages the service configuration, though an organization admin or the Lightdash team may still need to enable the feature.

### Self-hosted

A Self-hosted badge identifies instructions or settings that apply only to a deployment you operate. Follow the feature's setup instructions for its license, environment variables, and connected services.

## Enablement and permissions

Plan access does not automatically enable a feature. A page's availability callout identifies extra requirements, such as requesting a feature flag or setting a self-hosted environment variable.

Your role and data permissions still apply after a feature is enabled. Check the feature's prerequisites if you can open the page but cannot find a setting or perform an action.
