Enable the [Lightdash MCP server](/agents/lightdash-mcp) on your self-hosted instance and make its endpoint reachable by your AI clients. This page covers deployment configuration and network access; use the feature documentation for client setup, authentication, tools, and permissions.

## Prerequisites

- **Enterprise license** — `LIGHTDASH_LICENSE_KEY` must be set on your instance.
- **HTTPS** — MCP clients connect over HTTPS. See [secure Lightdash with HTTPS](/self-host/customize-deployment/secure-lightdash-with-https) if your instance is HTTP-only.

## Enable MCP

Set the following environment variable on your Lightdash backend, then restart it:

```bash
MCP_ENABLED=true
```

Lightdash includes the OAuth server; you don't need a separate OAuth service. Organization administrators can still [turn MCP access off](/agents/lightdash-mcp#turn-mcp-access-on-or-off), even when `MCP_ENABLED=true`.

## MCP URL format

Once enabled, the MCP endpoint is available at:

```text
https://<your-lightdash-host>/api/v1/mcp
```

Replace `<your-lightdash-host>` with your instance's domain (e.g. `lightdash.yourcompany.com`).

## Connect an AI assistant

Follow [Connect a client](/agents/lightdash-mcp#connect-a-client) to generate configuration using your instance's URL. For headless integrations, see [custom integrations](/agents/lightdash-mcp#custom-integrations).

## Network requirements

If your Lightdash instance sits behind a firewall or VPN, ensure the MCP client can reach it over HTTPS. See the [MCP network requirements](/agents/lightdash-mcp#network-requirements) for additional domains that may need allow-listing depending on the AI assistant.

The client needs `/api/v1/mcp`, the OAuth endpoints under `/api/v1/oauth/`, and the `/.well-known/oauth-*` discovery paths. Some clients connect from their vendor's cloud rather than from the user's machine, so an instance that's only reachable on your internal network works from one client and fails from another. For those clients, allow the vendor's published outbound IP ranges to reach these paths.

To check that the endpoint is reachable from a given network, run:

```bash
curl -i https://<your-lightdash-host>/api/v1/mcp
```

A reachable instance returns `401 Unauthorized` with a `WWW-Authenticate` header pointing at your `SITE_URL`. If that URL isn't the public HTTPS address of your instance, OAuth discovery fails.

## Troubleshooting

| Symptom | Likely cause |
| --- | --- |
| `/api/v1/mcp` returns an error or 404 | Check the license and deployment configuration, then confirm **Allow MCP access** is enabled in **Settings** → **MCP** → **General** |
| OAuth flow fails | The Lightdash instance isn't reachable from the browser performing the OAuth redirect |
| AI assistant can't connect | The MCP URL is wrong or the instance isn't accessible over HTTPS |
