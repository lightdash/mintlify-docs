Lightdash exposes a [Model Context Protocol](/agents/lightdash-mcp) server that AI assistants (Claude, ChatGPT, Codex, Cursor, VS Code, and other MCP clients) connect to for querying the semantic layer. Enabling it on a self-hosted instance is a one-flag change.

## Prerequisites

- **Enterprise license** — `LIGHTDASH_LICENSE_KEY` must be set on your instance.
- **HTTPS** — MCP clients connect over HTTPS. See [secure Lightdash with HTTPS](/self-host/customize-deployment/secure-lightdash-with-https) if your instance is HTTP-only.

## Enable MCP

Set the following environment variable on your Lightdash deployment:

```bash
MCP_ENABLED=true
```

The OAuth server is built into Lightdash, so no external OAuth configuration is needed — the authentication flow works the same way as it does on Lightdash Cloud.

## Optional configuration

<McpEnv />

Set `MCP_RUN_SQL_MAX_LIMIT` to override the default row cap of 5000 for the `run_sql` tool. It is tuned independently of AI Analyst and does not inherit `AI_COPILOT_MAX_QUERY_LIMIT`. For example:

```bash
MCP_RUN_SQL_MAX_LIMIT=20000
```

Requests that ask for more rows are clamped to this limit.

To reduce the filter-related query schema sent to the model, enable [compact filter expressions](/self-host/enterprise-features/ai-agents#compact-filter-expressions). That section covers deployment and client-refresh requirements.

## MCP URL format

Once enabled, the MCP endpoint is available at:

```text
https://<your-lightdash-host>/api/v1/mcp
```

Replace `<your-lightdash-host>` with your instance's domain (e.g. `lightdash.yourcompany.com`).

## Connect an AI assistant

In Lightdash, go to **Settings → MCP → Connect** and choose your AI assistant. The setup guide uses your self-hosted URL to generate the command or configuration to copy. See the [Lightdash MCP manual setup](/agents/lightdash-mcp#manual-setup) for client-specific instructions.

For example, with Claude Code:

```bash
claude mcp add --transport http lightdash 'https://<your-lightdash-host>/api/v1/mcp'
```

## Network requirements

If your Lightdash instance sits behind a firewall or VPN, ensure the MCP client can reach it over HTTPS. See the [MCP network requirements](/agents/lightdash-mcp#network-requirements) for additional domains that may need allow-listing depending on the AI assistant.

The client needs `/api/v1/mcp`, the OAuth endpoints under `/api/v1/oauth/`, and the `/.well-known/oauth-*` discovery paths. Some clients connect from their vendor's cloud rather than from the user's machine, so an instance that's only reachable on your internal network works from one client and fails from another. For those clients, allow the vendor's published outbound IP ranges to reach these paths.

For example, custom connectors in Claude.ai, Claude Desktop, and the Claude mobile app connect from Anthropic's cloud, while Claude Code connects from the user's machine. If Claude Code connects but the Claude connector reports that it can't reach your server, allow [Anthropic's outbound IP addresses](https://platform.claude.com/docs/en/api/ip-addresses) to reach the MCP and OAuth paths above.

To check that the endpoint is reachable from a given network, run:

```bash
curl -i https://<your-lightdash-host>/api/v1/mcp
```

A reachable instance returns `401 Unauthorized` with a `WWW-Authenticate` header pointing at your `SITE_URL`. If that URL isn't the public HTTPS address of your instance, OAuth discovery fails.

## Troubleshooting

| Symptom | Likely cause |
| --- | --- |
| `/api/v1/mcp` returns an error or 404 | `MCP_ENABLED` isn't set to `true`, or `LIGHTDASH_LICENSE_KEY` is missing or invalid |
| OAuth flow fails | The Lightdash instance isn't reachable from the browser performing the OAuth redirect |
| AI assistant can't connect | The MCP URL is wrong or the instance isn't accessible over HTTPS |
