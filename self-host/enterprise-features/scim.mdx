[SCIM 2.0](/workspace-admin/sso/scim) automates user and group provisioning from an identity provider (Okta, Azure AD, OneLogin, and any other SCIM 2.0-compliant IdP). On self-hosted instances the feature is off by default.

## Prerequisites

- **Enterprise license** — `LIGHTDASH_LICENSE_KEY` must be set on your instance.
- **A SCIM 2.0 identity provider** — Okta, Azure AD, OneLogin, or equivalent.
- **[SSO configured](/self-host/customize-deployment/use-sso-login-for-self-hosted-lightdash)** — required if SCIM is used alongside SSO, so users provisioned by SCIM can sign in through the IdP.

## Enable SCIM

Set the following environment variables on your Lightdash deployment:

| Variable | Example | Purpose |
| --- | --- | --- |
| `SCIM_ENABLED` | `true` | Main switch for SCIM. |
| `AUTH_ENABLE_OIDC_TO_EMAIL_LINKING` | `true` | **Required when using SCIM alongside SSO.** Links SSO sign-ins by email to users already provisioned by SCIM. Without it, Lightdash tries to create a new user on sign-in and fails because the email is taken. |

Restart the backend. Organization admins can then obtain a SCIM base URL and token from **Organization settings → SCIM** and enter them into the IdP's SCIM configuration. See [SCIM integration](/workspace-admin/sso/scim) for the provider-side steps.

## Verifying SCIM

1. Log in as an organization admin.
2. Open **Organization settings → SCIM**.
3. Confirm the SCIM base URL and **Generate token** action are available.
4. Configure the IdP with the URL and token, then trigger a test provisioning run from the IdP.

## Troubleshooting

**The SCIM section is missing from organization settings.**
Confirm `SCIM_ENABLED=true` and `LIGHTDASH_LICENSE_KEY` are set on every Lightdash container.

**Users provisioned via SCIM can't sign in through SSO.**
Set `AUTH_ENABLE_OIDC_TO_EMAIL_LINKING=true` and restart. Existing failed sign-ins will succeed on the next attempt.
