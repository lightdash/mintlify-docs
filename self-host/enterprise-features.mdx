Apply an Enterprise license key and configure licensed features on your self-hosted Lightdash instance. This section covers deployment setup; each feature links to its product documentation for usage and permissions.

For Lightdash Cloud availability, see the feature's product documentation and [Lightdash plans](https://www.lightdash.com/pricing).

## Get a license key

1. [Contact the Lightdash team](https://calendly.com/lightdash-cloud/enterprise?utm_source=docs&utm_medium=referral&utm_campaign=enterprise_licensing&utm_content=license_key_page) to request a self-hosted Enterprise license.
2. Obtain your license key from the Lightdash team.

## Apply the license key

Set `LIGHTDASH_LICENSE_KEY` on **every** Lightdash container: backend, scheduler, and workers.

<Tabs>
<Tab title="Environment variable">
```bash
LIGHTDASH_LICENSE_KEY=your-enterprise-license-key-here
```
</Tab>

<Tab title="Helm (Kubernetes)">
```yaml
secrets:
  LIGHTDASH_LICENSE_KEY: your-enterprise-license-key-here
```

Then update your deployment:

```bash
helm upgrade lightdash lightdash/lightdash -n lightdash -f values.yaml
```
</Tab>

<Tab title="Docker Compose">
```yaml
services:
  lightdash:
    environment:
      - LIGHTDASH_LICENSE_KEY=your-enterprise-license-key-here
```
</Tab>
</Tabs>

Restart every container after adding the key.

## License validation and network requirements

Lightdash validates the license before loading Enterprise services at startup. If your deployment restricts outbound traffic, review [Enterprise license validation](/self-host/data-flows-and-telemetry#enterprise-license-validation) and the [egress matrix](/self-host/data-flows-and-telemetry#egress-matrix) before restarting. Feature-specific setup pages describe additional connections to model providers, storage, and other services.

## Verify the license

After applying the key and restarting:

1. Log in to Lightdash.
2. Click the version number in the page footer to open **About Lightdash**.
3. Check the **Enterprise license** row: **Valid** means enterprise features are enabled, **Not valid** means the configured key failed validation, and **No license** means the server can't see a key.

### Embedding

To enable embedding on your instance, add `embedding` to `LIGHTDASH_ENABLE_FEATURE_FLAGS` and list the origins allowed to iframe your instance:

```bash
LIGHTDASH_ENABLE_FEATURE_FLAGS=embedding
LIGHTDASH_IFRAME_EMBEDDING_DOMAINS=https://app.example.com,https://reports.example.com
```

If `LIGHTDASH_ENABLE_FEATURE_FLAGS` already lists flags, append `embedding` to the comma-separated list. See [feature flags](/self-host/customize-deployment/environment-variables#feature-flags). Replace the example domains with your own origins, including the protocol and no trailing slash. The instance needs a valid license. Restart the backend, then follow [Set up embedding](/embed/set-up-embedding) to configure embed secrets and authentication. See the [embedding variables reference](/self-host/customize-deployment/environment-variables#embedding) for optional settings.

### Pre-aggregates

### Custom roles

To enable custom roles on your instance, add `custom-roles` to `LIGHTDASH_ENABLE_FEATURE_FLAGS`:

```bash
LIGHTDASH_ENABLE_FEATURE_FLAGS=custom-roles
```

If `LIGHTDASH_ENABLE_FEATURE_FLAGS` already lists flags, append `custom-roles` to the comma-separated list. See [feature flags](/self-host/customize-deployment/environment-variables#feature-flags). Restart the backend, then follow [Custom roles](/workspace-admin/custom-roles) to create and assign roles. The instance needs both a valid license and this flag.

### Live data sources

To enable [live data sources](/integrations/live-data-sources) on your instance, add `api-query-sources` to `LIGHTDASH_ENABLE_FEATURE_FLAGS`:

```bash
LIGHTDASH_ENABLE_FEATURE_FLAGS=api-query-sources
```

If `LIGHTDASH_ENABLE_FEATURE_FLAGS` already lists flags, append `api-query-sources` to the comma-separated list. See [feature flags](/self-host/customize-deployment/environment-variables#feature-flags).

To let people sign in to Google Analytics 4, Search Console, Google Ads and YouTube Analytics, set `AUTH_GOOGLE_OAUTH2_CLIENT_ID` and `AUTH_GOOGLE_OAUTH2_CLIENT_SECRET` to the Google OAuth client used for [Google sign-in](/self-host/customize-deployment/use-sso-login-for-self-hosted-lightdash), and enable the Google Analytics Data API, Search Console API, Google Ads API, YouTube Analytics API and YouTube Data API in its Google Cloud project. For Google Ads, also add the `https://www.googleapis.com/auth/adwords` scope to the client and apply for Google Ads API access for the project.

To let people sign in to PostHog, set `POSTHOG_OAUTH_CLIENT_ID` and `POSTHOG_OAUTH_CLIENT_SECRET`. Without them, people connect PostHog with a personal API key.

Restart the backend, then follow [Connect a live data source](/integrations/live-data-sources/set-up-and-manage#connect-a-live-data-source).

### Service accounts

A valid Enterprise license enables service accounts on your instance; no separate environment variable is required. For account creation, token rotation, and permissions, see [Service accounts](/workspace-admin/service-accounts).

### SCIM

To enable SCIM provisioning on your instance, add `scim-token-management` to `LIGHTDASH_ENABLE_FEATURE_FLAGS`:

```bash
LIGHTDASH_ENABLE_FEATURE_FLAGS=scim-token-management
```

If `LIGHTDASH_ENABLE_FEATURE_FLAGS` already lists flags, append `scim-token-management` to the comma-separated list. See [feature flags](/self-host/customize-deployment/environment-variables#feature-flags). The instance needs a valid license. When SCIM runs alongside OIDC SSO, also set `AUTH_ENABLE_OIDC_TO_EMAIL_LINKING=true` so sign-ins can link to SCIM-provisioned users. Restart the backend, then follow [SCIM integration](/workspace-admin/sso/scim) for identity-provider setup.

## Troubleshooting

If enterprise features are unavailable after applying the key:

1. Confirm `LIGHTDASH_LICENSE_KEY` is set on **every** Lightdash container (backend, scheduler, workers). On Kubernetes, check the environment of the running pod, not only the Secret: a Secret that exists but isn't mounted into the pod leaves the variable unset.
2. Confirm every container was restarted after adding the key.
3. Confirm the feature's required settings and connected services are configured using its setup page.
4. Check the [license validation network requirements](#license-validation-and-network-requirements).
5. Check the Lightdash logs for license-related errors.
6. Contact [enterprise support](https://calendly.com/lightdash-cloud/enterprise) if the issue persists.

Without a valid key, Lightdash starts without its enterprise services, even when the per-feature flag is set. Requests to those features then fail with an error like `Unable to initialize service 'serviceAccountService' - no factory or provider.` When the key is present but invalid, the backend logs a warning that starts with `Enterprise license for <SITE_URL>` on startup.
