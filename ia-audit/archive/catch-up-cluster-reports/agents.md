## Summary

Four things actually changed on `main` in this area: Deep Research was rewritten end-to-end (four commits landing on one end state — a bounded coordinator with up to two isolated workers, org-level limits replacing per-run depth, live report charts replacing snapshots, 30-day retention, and much wider availability); agent memory moved from feature-flag gating to an org-admin toggle and grew an FAQ; the external-MCP page gained a Slack-MCP setup walkthrough and a self-hosted backend-networking troubleshooting section; and small link-level additions mention parameters wherever agent query capability is enumerated, plus Slack channel auto-linking and a `Bearer` PAT alias for the Lightdash MCP endpoint.

Everything lands in pages that already exist on the branch — **no new pages, no redirects, no nav changes**. The MCP disambiguation (fe88b85) does not conflict: the Slack MCP server and the backend-networking troubleshooting are both agents-reaching-**out**, so both belong on `agents/connect-external-mcp-servers.mdx`; the `Bearer` PAT alias is external-assistants-reaching-**in**, so it belongs on `agents/lightdash-mcp.mdx`. Two genuine conflicts: Deep Research availability (branch says Enterprise + feature flag, `main` says wherever AI agents are enabled — `main` is newer and wins), and agent-memory gating (branch says feature flag, `main` says org toggle — same, `main` wins). Three of `main`'s additions carry prose the IA rules ban (changelog narration, a version parenthetical, a duplicated toggle description); those need trimming on the way in.
