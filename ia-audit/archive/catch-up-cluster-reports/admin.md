# Cluster: workspace-admin / integrations / embed / get-started

## Summary

Twelve `main` commits touch this cluster and they collapse into eight real content changes. The
big one is the query-tags expansion on `usage-analytics` — `d43881e` then `a957993` iterate on the
same table, and only the `a957993` end state matters. Two are genuinely new surfaces that need
placement decisions: an SSH-tunnel setup page and a pair of embed "try the demo" snippets. Two are
one-line factual corrections (OneLogin media-kit link, groups plan tier) that port verbatim.

The refactor and `main` do not contradict each other anywhere in this cluster — the refactor never
rewrote `usage-analytics`, `scim-integration`, `project-compilation-history`, or `export-limits`
beyond frontmatter and image paths, so those deltas apply cleanly at the new paths. The real work
is judgment, not conflict: `main` grew the Google Sheets page two extra jobs that don't fit the
Tutorial the refactor made it, and `main`'s embed change forks one fact across two near-identical
snippets plus a card grid.

Every ported line needs its `/references/*` and `/guides/*` links rewritten to branch paths —
they are listed per row and consolidated under Flags.

## Flags

1. **Where does the SSH tunnel page live?** (row 8) Three options: (a) `get-started/quickstart/connect-through-ssh-tunnel.mdx` as a fourth page in the quickstart group — **recommended**, it sits next to the connection reference that links to it and nothing else in the corpus covers warehouse network reachability; (b) an `<Accordion>` inside `connect-project.mdx`'s "Use SSH tunnel" field — rejected, that page is 8,974 words and already past the size trigger; (c) `self-host/` — rejected, the flow described is Lightdash Cloud → your bastion, so it is a Cloud connectivity concern. The one cost of (a) is that the quickstart golden path is deliberately three steps, and a private-VPC edge case is a fourth nav sibling.

2. **`main` forks the embed-demo fact three ways** (row 10). Two snippets whose only difference is a trailing sentence, plus duplicate `<Card>`s on the page that already transcludes a snippet. Principle 1 and 5 both point at one snippet; principle 12's card-grid restraint points at dropping the cards. Recommendation in row 10. If you disagree and want the iframe-specific example call-out preserved separately, keep two snippets but give them names that state the difference.

3. **`integrations/sync-google-sheets` has outgrown its Tutorial declaration** (rows 12, 14). The branch page is `doc-type: tutorial` + `tag: Tutorial` with `title: "Google Sheets"` — which already violates principle 6 (slug `sync-google-sheets` ≉ title "Google Sheets"). `main` then adds two jobs that are not the Syncs tutorial: an on-demand dashboard export and an add-on reference. Recommendation: **rename to `integrations/google-sheets.mdx`, `title: "Google Sheets"`, plain docs (drop `doc-type`/`tag`)** — one home for the Google Sheets integration, all three jobs, ~1,200 words total, well under the size trigger, and slug ≈ title is restored. Redirect `/integrations/sync-google-sheets` → `/integrations/google-sheets`, and **re-point** the two existing redirects at `docs.json:677` and `docs.json:1285` so they don't chain. The refactor's stated rationale in `move-map.csv:142` is only "verb-first tutorial", so nothing substantive is being undone. Alternative: keep the Tutorial and split the export + add-on onto a second page — rejected, that leaves two thin pages and splits one integration across two nav entries.

4. **"Alpha" is not a Lightdash maturity level** (row 14). `help/feature-maturity-levels` defines Experimental → Beta → GA. Map the add-on to `Experimental` on the way in; this is exactly the naming-drift the cleanup profile targets, and shipping `main`'s wording would put a fourth vocabulary word into the lifecycle taxonomy.

5. **`main`'s query-context table links MCP tool calls to the wrong page** (row 1). `/guides/ai-agents/mcp-servers` maps to `agents/connect-external-mcp-servers.mdx`, but `mcp.run_metric_query`, `mcp.run_sql`, and `mcp.search_field_values` are tools of the **Lightdash** MCP server (`agents/lightdash-mcp.mdx`). The refactor split these into two pages after `main` wrote the link; retarget on the way in.

6. **Cross-cluster dependencies.** Row 6 lands in `self-host/` (cluster-selfhost). Row 15's second link depends on cluster-dataapps placing `deliveries-and-syncs`. Row 17 lands in `workflow/` (cluster-workflow) — the `a57c11e` routing put an org-admin-flavored change into workflow-owned files.

7. **Consolidated link rewrites for ported content:** `/references/workspace/user-attributes`→`/workspace-admin/user-attributes`; `/references/workspace/custom-roles`→`/workspace-admin/custom-roles`; `/references/workspace/export-limits`→`/workspace-admin/export-limits`; `/references/workspace/roles`→`/workspace-admin/roles`; `/references/embedding`→`/embed/reference`; `/references/lightdash-cli`→`/workflow/cli/reference`; `/guides/developer/dashboards-as-code`→`/workflow/content-as-code`; `/guides/ai-agents/getting-started`→`/agents/set-up-agents`; `/guides/ai-agents/mcp-servers`→`/agents/lightdash-mcp`; `/guides/data-apps`→`/data-apps`; `/get-started/setup-lightdash/*`→`/get-started/quickstart/*`.
