# Cluster: semantic layer / dbt / pre-aggregates

## Summary

Eleven `main` commits land four independent bodies of content: two YAML filter operators (`inTheCurrent` / `notInTheCurrent`), a window-function limitation stated on dimensions and metrics, a model-level `meta.hidden` flag, and a large pre-aggregates expansion (external pre-aggregates as a whole new page, plus `sorts`, required-filter interaction, and operator-matching rules). Alongside those, "Connecting multiple dbt sources" was written once and corrected twice — **three facts were reversed and a naive port would reintroduce wrong information** (see Flags). The MetricFlow Beta work is nearly a no-op: the branch already declares `tag: "Beta"` in frontmatter, so only the body callout is new, and it should be reworded to the branch's house pattern.

The destinations all survived the refactor with their insertion points intact, so most rows are clean ports plus `references/` → area-path link rewrites. Three places genuinely conflict with refactor decisions: the pre-aggregates root page (the refactor trimmed §Filtered pre-aggregates to a pointer and relies on `directory: card`, so main's duplicate warning and its 4th hand-built card should not be ported), `workflow/cli/reference.mdx` (already documents `--combine-manifest` semantics that main restates on the dbt page), and the branch's five-mechanism sync reference on `dbt/projects.mdx`, which recommends `lightdash deploy` paths that multi-source projects must not use.

## Flags

1. **Three facts were reversed on `main` — do not port from `39ac8c0` or `c3332cc`.** Only `git show origin/main:references/integrations/dbt-projects.mdx` is true:
   - **Collisions.** Originally: a duplicate model name is resolved by precedence, the loser is dropped, and it's a *non-blocking warning*. **Truth:** compilation **fails**. Precedence no longer resolves collisions at all — it only determines which source is reported as holding the existing definition.
   - **Connector coverage.** Originally: additional sources support the same connection types as the primary. **Truth:** additional sources are **GitHub only**; the full set (GitHub, GitLab, Azure DevOps, Bitbucket, dbt Cloud) applies to the primary source only.
   - **Availability.** Originally: private beta, off by default, email support to enable. **Truth:** **enabled by default on Lightdash Cloud**; self-hosted needs `multi-dbt-sources` in `LIGHTDASH_ENABLE_FEATURE_FLAGS` on v0.3275.0+.
2. **`main` links `/references/table-calculation-functions` (row 2), which has no branch page and no redirect.** Ported verbatim it fails `mint broken-links` in four places. Retarget to `/explore/create-table-calculations`.
3. **The pre-aggregates Availability block is now in three places** — `semantic-layer/pre-aggregates.mdx:8`, `semantic-layer/pre-aggregates/audit-with-cli.mdx:10`, and (with row 12) the new external page. Identical text in 2+ pages is a snippet (principle 5). Recommend extracting `snippets/pre-aggregates-availability.mdx` and transcluding in all three as part of this work.
4. **The multi-source `lightdash deploy` prohibition contradicts the branch's sync recommendations.** `semantic-layer/dbt/projects.mdx:138-153` recommends `lightdash deploy` in CI (mechanism #2) as the production path for teams without a remote git connection, and `:175-177` nudges toward refresh-based patterns as merely "underused". For a multi-source project, `lightdash deploy` silently replaces the project's Explores with only the local repo's models. A reader who stops at § Recommended setups never reaches the warning buried in § Connecting multiple dbt sources. Add a one-line `<Warning>` to § Things to know pointing at it.
5. **`decide` — doc type for the external pre-aggregates page.** It has a five-step numbered workflow (Tutorial-shaped) wrapped around a comparison table, a column contract, an ownership split, and a limitations list (Reference-shaped). Options: (a) `doc-type: reference`, slug `external` — my recommendation; the definitional material is the bulk and the steps are a spine, not a journey, and it sits next to two other pre-aggregate references; (b) `doc-type: tutorial` + `tag: Tutorial`, verb-first slug `set-up-external-pre-aggregates` — cleaner type match for the numbered steps, but then the managed-vs-external table and the ownership split have to move to the landing page or getting-started, which is more churn than the content warrants; (c) split into both, which principle 10 argues against at ~1,400 words.
6. **Pre-existing branch issues in the blast radius, worth fixing while here.** All predate `main`'s changes; calling them out because rows 13-14 touch the same file:
   - `semantic-layer/pre-aggregates.mdx` has both `"directory": "card"` in nav and a hand-built `<CardGroup>` in the body (principle 12).
   - The same page sets `sidebarTitle: "Overview"`; principle 12 says "Overview" is not a sidebar item anywhere.
   - `semantic-layer/tables.mdx:1096` links the absolute URL `https://docs.lightdash.com/guides/explores`; `guides/` no longer exists. Should be `/semantic-layer/explores`.
7. **Two near-duplicate YAML filter-operator tables** (`semantic-layer/metrics.mdx` § Available filter types and `semantic-layer/tables.mdx` § Available filter types) both receive the same two rows in row 1. They differ in columns and row set, so they aren't a mechanical snippet extraction, but they are exactly the drift pattern principle 5 exists to stop — and this change is evidence of it. Recommend porting to both now (correctness first) and filing the unification (`snippets/yaml-filter-operators.mdx` with a single canonical operator table) as a separate cleanup-profile item rather than expanding this catch-up.
8. **Cross-cluster, self-host:** `self-host/customize-deployment/environment-variables.mdx:175` lists example values for `LIGHTDASH_ENABLE_FEATURE_FLAGS`. Adding `multi-dbt-sources` there would let row 5's Availability block link out instead of re-explaining the env var.
