<Note>
🛠 This page is for engineering teams self-hosting their own Lightdash instance.
</Note>

<Warning>
🔑 **Enterprise feature** — the AI thread debug dump requires a valid [Enterprise License Key](/self-host/customize-deployment/enterprise-license-keys) and only works when [AI Analyst](/self-host/customize-deployment/environment-variables#ai-analyst) is configured.
</Warning>

## What it is

Organization AI admins can download a sanitized JSON dump of any AI agent thread from **Settings → Ask AI → Threads**, using the per-row download action. The dump is designed to be shared with Lightdash support when troubleshooting agent behaviour without exposing customer data by default.

## Prerequisites

- A self-hosted Lightdash instance with a valid `LIGHTDASH_LICENSE_KEY`.
- [AI Analyst enabled](/self-host/customize-deployment/environment-variables#ai-analyst) (`AI_COPILOT_ENABLED=true` and a configured provider).

## Enable the feature

The thread debug dump is disabled by default. Set the following environment variable on your Lightdash deployment:

```bash
AI_COPILOT_THREAD_DUMP_ENABLED=true
```

Restart the Lightdash service to pick up the change. Once enabled, the per-row download action appears on threads in **Settings → Ask AI → Threads** for eligible users.

## Who can download a dump

Only organization-level AI admins can download thread dumps. Concretely, the user must have `manage` permission on the organization's AI agents. Project-scoped agent managers cannot download dumps, even for threads inside a project they manage.

For a refresher on the underlying roles, see [Workspace roles](/references/workspace/roles).

## What the dump contains

Each dump is a single JSON file that includes:

- **The full conversation** — every user prompt, agent response, and tool call, including tool arguments.
- **Agent configuration as of download time** — the agent's instructions, model, and feature toggles.
- **The Lightdash version** the instance was running at download time.
- **UUIDs only** — no user names or email addresses are included.
- **Chart and dashboard artifact configs** produced by the agent during the conversation.

## What is redacted

The dump uses a deny-by-default allowlist for tool output. The following are stripped or reduced before the file is written:

- **Query result rows** — column names and row counts are kept; the row values themselves are removed.
- **Field value searches** — search terms and results are stripped.
- **Unclassified tool output and MCP tool output** — dropped rather than included by default.
- **Customer documents** and **repository contents** the agent may have read during the conversation.

## Accepted risks

The dump is a support-oriented artifact, not a fully anonymized export. Before enabling the feature or sharing a file, make sure your team understands the following:

- **Agent responses may quote data verbatim.** Redaction covers tool output, not the natural-language answers the agent wrote. Admins must review the file before sharing it.
- **Downloaded files leave Lightdash's retention window.** Once a dump is on disk, Lightdash cannot delete or expire it. The customer owns its lifecycle from that point on.
- **End users are not notified** that their agent conversations may be shared. Organizations with internal privacy-notice obligations (for example, EU works councils) should document this internally before enabling the feature.

## Auditability

Every dump download emits an `AiAgentThreadDump` audit log event that records the actor, the thread, and the source IP address. Audit events are written at the `audit` log level, so they are only collected when the instance runs at that level or lower:

```bash
LIGHTDASH_LOG_LEVEL=audit
```

`LIGHTDASH_LOG_LEVEL=debug` also includes audit events. See [Configure logging for Lightdash](/self-host/customize-deployment/configure-logging-for-lightdash) for the full logging setup.

If [Rudderstack telemetry](/self-host/customize-deployment/environment-variables#analytics--event-tracking) is enabled on the instance, a matching `ai_agent.thread_dump_downloaded` telemetry event also fires on each download.

## Point-in-time caveat

The `agent configuration` block in the dump reflects the agent's settings at the moment of download, not at the time of the conversation. If instructions, model, or toggles changed after the thread ran, the block shows the current values.

Per-turn model configuration is historical, so the specific model used for each response in the conversation is preserved even if the agent's default model has since changed.
